# PS5 Homebrew UI library review and roadmap

I’d make **opening a large library, finding a title, entering its detail screen, and backing out to the exact same card** the project’s next flagship experience. That one flow exercises the qualities people notice from a sofa: whether focus is obvious, artwork arrives smoothly, animations follow the controller, and the app remembers where they were.

I reviewed `f599199`, covering the catalog of **99 components across 15 families**, all **30 theme definitions** and their gallery images, and the **21 showcase designs**. I also sampled the animation reels, measured theme colors, and ran targeted host probes. The performance figures below come from the project’s recorded console tour. This review added no hardware measurements or repository changes. [Component catalog](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/docs/COMPONENT_INDEX.md) · [Showcase](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/docs/DESIGNS.md)

## Fixes I would ship first

| Priority | Finding | Proposed fix |
|---|---|---|
| 1 | **A long list can reopen blank.** I restored a 1,001-row `ListView` to index 1,000. After one second, zero visible rows drew content. After 31 seconds, five drew. The default entrance delay is 30 ms times the absolute row index. | Stagger from the first visible row, as `GridView` already does. Draw the restored focus immediately and limit traversal to visible rows plus a small margin. [List entrance](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/ui/components/list.cpp#L193) · [Grid implementation](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/ui/components/grid.cpp#L325) |
| 2 | **Changing list density can overlap rows, and a section header can activate.** Changing row height from 76 to 120 left the next row only 82 pixels below the first. Calling `set_focus()` on a header and pressing Confirm returned `activated`. I reproduced both. | Invalidate cached row positions when layout metrics change. Route focus restoration through the same eligibility rules as D-pad navigation, including a defined result for a list containing only headers. [List geometry and focus](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/ui/components/list.cpp#L17) |
| 3 | **Some controller hints contradict the active mapping.** Input honors swapped Confirm/Back. Aurora’s sheet still draws Cross for “Choose” and Circle for “Back.” | Let hints accept logical actions and resolve them through the existing `button_for()` mapping. Test the same dialog in both configurations. Keep physical glyphs available for instructions that genuinely mean a particular button. [Aurora hints](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/concepts/aurora.cpp#L590) · [Existing mapping](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/ui/components/action_glyph.hpp#L22) |
| 4 | **The keyboard can exceed its character limit.** With a maximum of 12 and a current length of 11, tapping the built-in `.com` key emitted all four characters and reported a length of 15. | Check the entire insertion before emitting it. Refuse a shortcut that cannot fit, with one feedback cue. Give the keyboard and text field one shared rule for counting and deleting user-perceived characters, including a letter plus a combining accent. [Keyboard emission](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/ui/components/keyboard.cpp#L566) · [Unicode text segmentation](https://www.unicode.org/reports/tr29/) |
| 5 | **Several theme colors make labels hard to read.** I measured the opaque primary-label and fill tokens at **1.95∶1 in Friendly** and **2.58∶1 in Candy**. Featherweight’s muted text against its surface is **2.51∶1**. | Preserve each theme’s accent and adjust its foreground first. Test ordinary text against a 4.5∶1 target and large text against 3∶1. For glass, gradients, and artwork, check the rendered composition too. [Theme definitions](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/ui/theme.cpp) · [W3C contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) |
| 6 | **Reduce Motion still leaves decorative movement in the component gallery.** The gallery passes its running clock to the backdrop and uses it to move four pools of light behind Acrylic. | Separate decorative time from interaction time. Freeze backdrop drift and parallax while preserving focus changes, meaningful progress, and short fades. Add a host check that compares two settled frames with Reduce Motion enabled. [Gallery drawing](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/concepts/components.cpp#L140) |

One small documentation fix belongs with these: the theme guide says the kit has no data table, tree, or date picker. All three are in the catalog. An app developer evaluating the library could easily miss them. [Theme guide](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/docs/THEMES.md#L566) · [Component index](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/docs/COMPONENT_INDEX.md)

## Enhancements that would make the library feel more polished

**Make screen transitions reversible.** The kit already has springs, focus highlights, and a `Transition` component. Its `start()` and `leave()` methods reset elapsed time. Add a mode that can reverse from the currently drawn position, scale, and opacity. The first use should be a cover expanding into a detail hero. Pressing Back halfway through should send that same cover home smoothly. Holding Right across a shelf should move focus immediately while the hero art settles on the final selection. [Transition implementation](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/ui/components/transition.cpp#L11)

**Make real artwork as easy to use as demo artwork.** The showcase generates its covers up front. A real library needs stable item IDs, cancellable image requests, a bounded texture cache, and a placeholder that occupies the final image rectangle. Decode off the frame thread, budget uploads on the render thread, and discard stale completions. A fast scroll through 500 covers should never put the previous title’s art on the newly focused card. [Demo artwork](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/demo/catalog_art.cpp) · [Virtual grid API](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/ui/components/grid.hpp#L74)

**Give every theme a large-text and high-legibility mode.** The project already has a dedicated Contrast theme and adjustable hint size. A player should also be able to keep Acrylic or Sketch while enlarging body text, reducing transparency, and strengthening the focus outline. Start with settings rows, dialogs, and keyboard prompts. Test long labels, two-line values, focus visibility, and footer collisions. The adoption guide already records downstream experience with font fallback, text shaping, and right-to-left text that can inform this work. [Player settings](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/core/settings.hpp) · [Adoption notes](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/docs/ADOPTING.md#L117)

**Ship a small consumer build target.** Today, adopters are instructed to copy source directories. Offer a versioned library target and one minimal external app that opens a settings screen, pushes a detail screen, and returns focus. Build that consumer in CI. It would catch accidental showcase dependencies and give developers a much shorter path to their first working app. [Current adoption workflow](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/docs/ADOPTING.md)

## New widgets worth building

| Widget | What it should do on a controller |
|---|---|
| **Shelf browser** | Stack horizontal shelves vertically. Remember the last focused item in each shelf, restore by stable ID after a refresh, and handle a removed item gracefully. Build it on the existing card and collection machinery. |
| **Search and filter panel** | Combine `SearchField`, recent searches, filter chips, sorting, and a results count. Let the player edit several filters, apply them once, and return to the original result when they clear the filter. |
| **Task and transfer center** | Show queued, active, paused, failed, and completed work. Expose progress, retry, cancel, and an intelligible failure reason. Reuse `ProgressBar`, `NotificationCenter`, and `Dialog` so apps supply job state and callbacks. |
| **Artwork detail header** | Compose a full-width image, adaptive text scrim, metadata, and primary action. Keep the title readable on a nearly white cover. Maintain the layout when art is absent or arrives late. Pair it with the shelf-to-detail transition. |
| **Caption and track picker** | Extend `MediaControls`, which already supports seeking and chapter marks. Add audio and subtitle selection, a live caption preview, text size, and background opacity. Return focus to the transport control that opened it. [Media controls](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/src/ui/components/media_controls.hpp) |

## Three themes with distinct visual identities

| Theme | Visual and motion direction | Best showcase |
|---|---|---|
| **Cinema** | Near-black surfaces, warm white type, full-bleed artwork, and a scrim that deepens behind text. The focused cover expands into the hero while the title stays anchored. Reduced Motion uses a dissolve. | Film library or game detail page |
| **Field Journal** | Warm stock, charcoal text, restrained ochre rules, and generous margins. Use quiet serif headings and a margin marker that slides to the current section. Give long-form reading and diagrams equal care. | Game codex, manual, or save archive |
| **Broadcast** | Deep navy, white tabular figures, amber live markers, and compact lower thirds. Changed values settle independently so the rest of the screen stays readable. Pair status colors with shapes and labels. | Download monitor, media dashboard, or tournament overlay |

I’d ship **Cinema first** because it forces the artwork loader, focus restoration, contrast treatment, and reversible transition to work together. Field Journal would then stress typography and localization. Broadcast would stress frequent updates and information density.

## Release order and acceptance criteria

1. **Correctness release.** Land the six fixes above with focused regression tests. Add a small visual CI matrix covering Acrylic, Pixel, Sketch, Friendly, and Contrast. Capture focused, disabled, modal, and reduced-motion states using the existing host tour.
2. **Flagship library release.** Ship the shelf browser, artwork detail header, image loading, and Cinema together. The acceptance tour should restore focus at item 1,000, reverse a transition halfway through, survive a failed image load, and return to the same item after a filter change.
3. **Consumer release.** Build the external sample against the packaged library. Run the flagship tour on hardware and record 4K frame pacing, peak texture memory, and time to first interactive frame. The repository’s existing baseline covers **39,956 console frames on build `044d909`**. Use it as a comparison point for the new workload. [Recorded console measurements](https://github.com/BlackBearRevived/ps5-homebrew-ui/blob/f599199/docs/PERFORMANCE.md#measured)

The acceptance test I’d put in front of the team is simple: **hold Right through uncached covers, open one, press Back before the animation finishes, and carry on navigating.** If the artwork, focus, sound, and frame pacing all stay coherent through that sequence, developers will feel the value of the library in their first five minutes.
